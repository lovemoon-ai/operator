# 镜像壳体使用相同旋转导致无支撑空中挤出

- Date: 2026-09-04
- Status: Active
- Incident artifact: `left_cache.stl` / `right_cache.stl`

## Trigger Conditions

以下任一条件出现时，本 lesson 适用：

- 同盘包含左右镜像件。
- 盒体、罩壳、杯状件或有明显内腔的零件。
- 一个对象的旋转直接复制给另一个对象。
- 为降低高度而进行 90° 翻转。
- 支撑关闭或仅依赖自动桥接。

## Symptom

成品壳体内出现大量长线、线团或“意大利面”，墙体可能仍基本完整。该现象容易被误判为
湿料、回抽不足或普通拉丝，实际可能是喷头在大面积空腔上方无承托挤出。

## Direct Cause

左右镜像件都使用 `X +90°`：

- `right_cache` 的开口朝上，封闭底面落在打印盘上。
- `left_cache` 的开口朝下，只剩边缘接触打印盘，后续必须跨越内腔封顶。

正确的镜像方向应分别评估；本次几何对应：

```text
left_cache  -> X -90°
right_cache -> X +90°
```

## Evidence

床面接触面积：

| 对象与方向 | 接触面积 |
| --- | ---: |
| `left_cache`, 错误 `X +90°` | 约 `997 mm²` |
| `left_cache`, 正确 `X -90°` | 约 `6250 mm²` |
| `right_cache`, 正确 `X +90°` | 约 `6250 mm²` |

错误方向的接触面积只有正确方向约六分之一。

最终 G-code 中：

- 支撑为关闭状态：`enable_support=0`。
- 失败对象在约 `Z=36.8–39.2 mm` 出现跨越大部分内腔的 Bridge/Floating shell。
- 主要风险区域约覆盖 `84 × 149 mm`，远超普通可接受桥接。

## Root Cause

- 朝向算法只关注包围盒高度，没有识别开口、封闭底面和内腔。
- 镜像件复用了相同旋转矩阵，没有独立评估。
- 多个 STL 被合并成一个对象，失去逐对象审核能力。
- 切片后检测到大型 Bridge/Floating shell，但没有设置阻断条件。
- 没有检查风险层预览。

## Required Controls

1. 左右镜像件分别计算候选朝向，不复制旋转结论。
2. 对壳体识别开口侧、封闭底面和内腔；默认开口朝 `+Z`。
3. 对每个候选记录床面接触面积和朝下水平面积。
4. 保持每个零件为独立对象。
5. 支撑关闭时，按对象检查 Bridge、Floating shell 和新生孤岛。
6. 强制查看壳体风险层和开口方向预览。

## Blocking Conditions

以下任一条件存在时禁止打印：

- 镜像件使用相同旋转，但未分别提供朝向证据。
- 开口方向不明。
- 选定方向的床面接触面积显著小于另一候选，且没有功能性理由。
- 内腔上方出现接近内腔宽度的大跨度挤出。
- 支撑关闭且 Bridge/Floating shell 没有可靠承托来源。
- 左右件风险统计出现数量级差异但未复核。

## Verification Evidence

打印报告必须包含：

- 每个镜像件的旋转、开口方向和床面接触面积。
- 每个对象的 Bridge/Floating shell 层号、Z 和最大跨度。
- 风险层预览。
- 支撑决策及理由。

## Recovery

- 不通过增加大量支撑掩盖明显错误朝向；先修正朝向。
- 只重打失败对象，不重复消耗已合格零件。
- 正确朝向后重新切片并执行完整 Lesson Gate 和发布审核。
