# Bambu 打印审核与发布 SOP

本文件只定义从模型输入到打印完成的主流程。具体事故模式、判据和防复发控制保存在
`lessons/`；不要把单次事故细节继续堆入本 SOP。

## 核心规则

- 执行四个强制关卡：**需求、几何、切片、发布**。
- 检查结果使用 `PASS`、`WARN`、`FAIL`、`UNKNOWN`。
- `FAIL` 禁止打印；`UNKNOWN` 默认按 `FAIL` 处理。
- `WARN` 必须写入发布报告，并由用户明确接受。
- 用户授权绑定到最终 `gcode.3mf` 的 SHA-256；文件变化后重新审核和授权。
- 打印命令只提交一次。失败、超时或状态不明时先只读查询，不自动重试。
- 只有状态进入 `RUNNING` 才能报告已开始，进入 `FINISH` 才能报告已完成。

## Lesson Gate

每次准备实际打印前，先运行 `../scripts/list_bambu_lessons.sh` 校验索引并列出全部 lesson，
然后读取 `lessons/README.md` 和脚本列出的每篇 lesson。

在任务报告中为每篇 lesson 记录：

```text
lesson: lessons/<file>.md
applicability: APPLIES | NOT_APPLICABLE
reason: ...
controls_applied: [...]
evidence: [...]
status: PASS | WARN | FAIL | UNKNOWN
```

要求：

- 不能依赖记忆跳过 lesson 文件。
- `APPLIES` 的 lesson 必须执行其中的防复发检查，并提供证据。
- `NOT_APPLICABLE` 必须说明原因。
- lesson 索引缺项、适用性未判断、证据缺失或状态为 `FAIL/UNKNOWN` 时禁止打印。
- 新失败或险情完成根因分析后，先新增一篇 lesson 并登记到索引，再进行下一次相关打印。

## 任务目录

每个打印任务建立独立目录：

```text
print-job/
├── source/              原始输入，只读保存
├── prepared/            修复、朝向和排版后的项目
├── sliced/              最终 gcode.3mf
├── previews/            布局、首层、支撑和风险层预览
├── report.json          机器可读审核结果
└── report.md            用户审核报告
```

不得修改 `source/` 中的文件。

## 1. 需求关卡

确认并记录：

- 输入文件、零件名称和数量。
- 目标打印机、喷嘴、盘号和打印盘类型。
- 材料种类、颜色及 AMS 要求。
- 零件用途，以及强度、外观、精度和速度优先级。
- 外观面、装配面、承力面、配合公差和允许的支撑痕迹。
- 是否允许自动修复、自动朝向和自动支撑。

关键需求不明确时询问用户；非关键默认值必须写入报告，不能静默猜测。

## 2. 冻结输入

为每个输入文件记录：

- 绝对路径、格式、大小和修改时间。
- SHA-256。
- 预期对象和数量。

复制到 `source/`。后续发现文件变化时，从本步骤重新开始。

## 3. 几何关卡

逐个对象检查：

- 尺寸、单位和包围盒符合预期。
- 网格非空，坐标有限。
- 法线、流形、自相交、退化面和重复面状态可接受。
- shell 数量正确，无意外碎片。
- 单个 STL 含多个互不连通的 closed shell 时，必须逐个识别并确认期望物理零件数；未经确认不得把它们解释为同一零件。
- 多 shell 的包围盒、相交/贴合关系和最小间隙必须检查；需要分开的零件必须拆成独立对象并分开排布。
- 薄壁、孔、文字和细小结构适合当前喷嘴及层高。
- 修复没有改变主要形状、尺寸或对象数量。
- 模型未超过打印机成型范围。

多零件任务保留为独立对象，以便分别设置朝向、支撑、brim、接缝和材料。不要为了绕过
单输入限制而静默合并成一个 STL。

## 4. 朝向与布局

逐个对象评估原始方向、稳定底面、打印高度、支撑需求、外观面、装配面和承力方向。选择的
方向必须有可审计理由，不能只根据最低高度决定。

布局检查：

- 对象、brim 和支撑均在可打印区域内。
- 对象、brim 和支撑互不重叠，并留有合理间距。
- 接触面积和重心满足稳定性要求。
- 默认逐层打印；逐对象打印必须完成工具头碰撞检查。
- 输出每个对象的位置、旋转、包围盒和顶视布局预览。

本阶段必须应用 Lesson Gate 中所有与对象形态、朝向和布局相关的 lesson。

## 5. 打印机与材料预检

通过 CLI 只读检查确认：

- 目标 profile 和打印机序列号正确。
- 打印机在线，且没有活动任务。
- 机器型号、喷嘴和打印盘与切片配置一致。
- AMS tray、材料类型、颜色和余量正确。
- 切片材料 preset 与实际材料匹配。

要求用户确认打印盘已清空并清洁，喷头与机构附近无残料、工具或旧打印件。

## 6. 切片配置

记录展开后的关键参数，而不只记录 preset 名称：

- Machine、process、filament preset。
- 喷嘴、打印盘、层高和首层高度。
- 墙数、顶底层、填充密度和图案。
- 支撑类型、阈值、界面和作用范围。
- Brim、接缝和打印顺序。
- 调平、流量校准、振动校准和延时摄影。

支撑决策应基于对象形态、孤岛、桥接、悬垂、外观面和可拆除性；不能只沿用默认开关。

## 7. 切片关卡

生成并保存：

- 保留独立对象的项目 3MF。
- 最终 `gcode.3mf`。
- preset 快照、切片器版本、命令和日志。
- 布局、首层、支撑、悬垂/桥接和风险层预览。

自动检查至少包括：

- 3MF 归档、plate、printer model ID 和 G-code 完整。
- 层数、挤出、材料密度和用量有效。
- 对象数量正确，没有对象消失或重叠。
- 第一层包含全部目标对象，接触面积合理。
- 模型打印阶段的 XYZ 范围位于成型区域。
- 孤岛、桥接、悬垂、floating shell 和支撑按对象统计。
- 支撑和 brim 确实覆盖预期区域。
- 机器、喷嘴、打印盘、材料元数据和 AMS mapping 一致。

预览必须至少审核：顶视布局、第一层、支撑、悬垂/桥接，以及所有风险层。无法生成关键预览
时状态为 `UNKNOWN`。

本阶段必须重新应用所有与 G-code、支撑、桥接、运动范围和预览相关的 lesson。

## 8. 发布关卡

提交打印前向用户提供报告：

```text
目标打印机和打印盘：...
输入文件、对象数量和 SHA-256：...
每个对象的方向、尺寸和位置：...
材料、颜色和 AMS tray：...
喷嘴、层高、墙数、填充、支撑和 brim：...
层数、预计时间和耗材：...
孤岛、桥接、悬垂和 floating shell：...
自动修复与所有 WARN：...
Lesson Gate 结果：...
最终 gcode.3mf SHA-256：...
预览文件：...
```

只有报告没有 `FAIL`、没有未豁免的 `UNKNOWN`，并且用户明确批准该 SHA-256，才能提交。

## 9. 提交前复核与发送

用户授权后立即复核：

- 最终文件 SHA-256 未变化。
- 打印机仍为空闲状态。
- AMS tray、材料和余量未变化。
- 连接正常。
- 用户已确认打印盘和机构安全。

先运行支持的 dry-run，再执行一次真实命令。命令细节见 `cli-reference.md`。

## 10. 提交后确认

区分以下阶段：

1. `SUBMITTED`：上传或任务创建成功。
2. `PREPARE`：打印机开始准备。
3. `RUNNING`：实际打印开始。
4. `FINISH`：打印机报告任务完成。

LAN 使用 `status`/`watch`；Cloud 使用 `cloud doctor` 查询状态快照。状态字段不能证明首层、
翘曲、拉丝或支撑外观正常；没有可靠视觉证据时要求用户从打印机屏幕确认。

## 11. 完成与复盘

打印结束后记录实际时长、材料、首层、翘曲、桥接、悬垂、接缝、支撑拆除、尺寸和装配结果。

出现失败、明显缺陷或险情时：

1. 保存照片、输入、最终 3MF、G-code、配置和状态记录。
2. 区分症状、直接原因、根因和促成因素。
3. 提取可机械执行的防复发检查。
4. 在 `lessons/` 新增一篇独立 Markdown。
5. 更新 `lessons/README.md` 索引和适用条件。
6. 必要时只在本 SOP 增加新的通用关卡，不把事故细节复制回 SOP。

## 通用阻断条件

- 输入 hash、对象或数量变化。
- 尺寸、单位或关键需求不明确。
- 模型、brim 或支撑越界或重叠。
- 对象在切片后消失。
- 第一层缺少目标对象。
- 存在无法解释或未承托的孤岛/大跨度挤出。
- 打印机、喷嘴、材料、打印盘或 AMS 映射不匹配。
- 材料余量不足。
- 3MF/G-code 校验失败。
- 打印机已有活动任务。
- Lesson Gate 未完成。
- 报告含未解决的 `FAIL` 或未豁免的 `UNKNOWN`。
