# 双臂、腰部、升降与末端

证据边界：本会话验证了官方源码和已部署路径，**没有实际控制过上半身动作**。不能称双臂/腰部/升降已实测成功。最后尝试 SSH 时机器人曾超时；先恢复当前通信。

## G1-D 专用关节映射

官方 example/g1/g1d/g1d_arm_example.cpp：

| 部位 | 索引 | 顺序 |
|---|---|---|
| 腰部 | 12、14 | yaw、pitch |
| 左臂 | 15–21 | shoulder pitch/roll/yaw、elbow、wrist roll/pitch/yaw |
| 右臂 | 22–28 | 同上 |
| 无效位置 | 0–11、13 | G1-D 的腿部和 waist roll 槽位无效 |

数组有29个槽位，不意味着29个有效 G1-D 关节。示例里的 WaistA/WaistB 别名也标记为无效，不能套并联腰控制。先核对本机 SDK、固件及电机状态的映射。

## DDS 关节控制

- 状态 `rt/lowstate`：`unitree_hg::msg::dds_::LowState_`。
- 命令 `rt/lowcmd`：`unitree_hg::msg::dds_::LowCmd_`。
- 躯干 IMU `rt/secondary_imu`：`IMUState_`。
- 命令字段包括 q（rad）、dq、kp、kd、tau、motor mode、mode_machine、mode_pr 和 CRC。照本机 SDK 数据定义处理，不手工猜消息布局。

实机接管流程：
1. 先只读关节角、速度、故障、机型模式和控制服务。确认远程操作者、疲劳测试、XR 等不会同时下发命令；不要直接 kill 正在托住负载的控制器。
2. 将需要保持的有效关节目标初始化为当前实际角度，不把整组 q 初始化成零姿态。
3. 以有限速度/加速度轨迹过渡到目标，核对各关节限位、手臂与躯干/环境碰撞、抓取负载。
4. q/dq/增益与机型模式、CRC 一致。使用持续定时循环及新鲜反馈看门狗。
5. 定义正常结束、撤销、失联的接管/保持/阻尼行为。上肢支撑力问题不同于底盘，**不能把底盘“发零速度”或上肢“断扭矩”当通用安全停机方式**。
6. 从小幅、单组动作开始验证并保留状态报告。

官方 arm 演示等遥控器 A 键后让双肩按约 ±30° 正弦摆动，不是“只检查通信”；且例程 control_dt=0.002 与 sleep(5ms) 并不一致。不要盲跑、照抄循环频率或将样例 kp/kd 当实机推荐值。其退出路径也不是完整的稳妥接管实现。

官方 generic G1 ArmAction/G1 walking/high_level 示例没有在本机 G1-D 验证，不能因为目录也叫 g1 就认定适用。

“手掌前移10厘米”是末端笛卡尔目标，需要匹配 G1-D URDF/工具坐标的运动学、逆解及轨迹规划；不是直接把 xyz 写到 q，也不能将 .1 当10厘米关节角。

## 升降柱

官方接口 `AgvClient.HeightAdjust(vz)`：
- 输入归一化速度 [-1,1]，不是米、目标高度或直接 m/s。
- 正值上升、负值下降、0 停止。
- 官方当前头文件给出的最大映射 76.5mm/s 与产品资料约60mm/s并不一致；不能当本机精确标定。
- 官方高度反馈：`rt/hispeed_state`，`geometry_msgs::msg::dds_::Point32_` 的 y，单位米。
- 指定高度需闭环反馈，软/硬限位、数据超时、最大时长、有限次停止以及实际停止确认。

`example/g1/g1d/g1d_height_control.cpp` 可作 API 和反馈字段参考。它没有为所有机型实现目标高度合法区间、整体最长执行时限和所有信号的安全退出，运行前补足；其等待首帧逻辑也不能无限等。

机械臂轨迹和升降同时控制需要额外协调空间/负载，不因用户只说“上半身”就自动一起动。

## 末端

先确认安装的是哪种夹爪/灵巧手，再选择对应驱动、映射和限力。曾看到 dex3 主题，不代表每台装的都是 Dex3；没有实测本机末端动作。示例和 URDF 必须与实际末端一致。
