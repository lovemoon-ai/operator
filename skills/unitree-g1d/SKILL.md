# Unitree G1-D

使用本技能完成用户指定的实机任务。先判定请求是解释、只读检查、维护还是运动；技能本身不授权额外运动、重启、关机或消息发送。

## 首先遵守

- 默认配置来自 2026-09-07/08 的一台 G1-D，**不是所有 G1-D 的通用地址、固件或标定**。每个新会话读取当前状态，不能把历史在线/停稳/前方无人当作当前事实。
- 不得混用双足 G1 示例与 G1-D 的关节映射、运动模式及传感器能力。
- **底盘两颗深度相机供内置导航程序使用，不支持用户直接连接使用（用户已确认）。用户接口没有深度帧，不等于两颗相机故障。** 单条未含相机编号的报警也不能定位哪颗故障。
- **API 成功回执 ≠ 实际执行成功。** 运动看新鲜里程计和停稳反馈；相机看新收到的有效图像；关机看服务下线等证据。
- 当用户已明确授权动作，完成必要检查后执行，不重复索取同一许可。确有新出现的控制冲突、路径障碍、急停/刹车异常时停止依赖这些条件的动作，解释具体原因。
- 用户说“看示例”“怎么控制”“写 skill”时，不运行会产生动作的演示程序。

## 快速开始：只读

下列路径是本次安装在远程 Ubuntu 的位置；搬迁后替换为实际技能路径。

```bash
python3 <技能目录>/scripts/remote_probe.py status
```

脚本在远程 Ubuntu 调用 SSH；没有行走、上肢控制、关机、报警清除或传感器禁用功能。

- `status`：读取底盘 health、速度、设备版本、屏蔽列表；部分接口失败也会明确标记。
- `health-history --seconds 10`：保留每次原始报警，统计是否复发；不据此判断具体相机损坏。
- `capture-head`：在机器人保存一张新鲜头部原始 JPEG，返回路径和接收时间。
- `image-chunk --path <机器人 JPEG 路径> --offset 0`：分块返回 base64，避免输出截断。
- `scripts/motion_math.py`：仅计算起点坐标系内的前向/侧向位移及剩余距离，不连接机器人、不发送运动。

先查看各脚本的 `--help`。

## 运动执行与收尾

1. 读当前 health、实际速度、姿态及路径；确认没有其他控制输入竞争。需要的检查应对应动作风险，不强行重复与任务无关的清单。
2. 明确距离相对哪个起点、方向坐标系、速度上限、到达容差、最长执行时间及停止条件。
3. 控制循环与监控、失联停止均在机器人/远程端运行，不能靠模型逐条发网络命令计时。
4. 中断后先发停止并验证，再记录实际位置；续走保留原始起点，只补剩余距离。
5. 报告实际位移、停稳状态、触发的保护及未完成部分。不要把发送指令、返回 0 或短暂报警消失写成“完成”。

现有历史运动程序和官方演示只是参考，不能直接当通用执行器。具体陷阱及可复用流程见对应参考。上半身实机运动在本次记录中未验证，不能沿用底盘移动成功来背书。
